# 接線與電源

前提：一顆 **5V** 的 28BYJ-48、ULN2003 驅動板、AI-Thinker ESP32-CAM（classic ESP32）、LM2596 降壓模組。若馬達銘牌是 12V，先停止接電。

## 正常運轉

| 從 | 接到 |
|---|---|
| 變壓器 +（9–12V） | LM2596 IN+ |
| 變壓器 − | LM2596 IN− |
| LM2596 OUT+（5.0V） | ESP32-CAM **5V**、ULN2003 **+** |
| LM2596 OUT− | ESP32-CAM **GND**、ULN2003 **−** |
| ESP IO12 | ULN2003 IN1 |
| ESP IO13 | ULN2003 IN2 |
| ESP IO14 | ULN2003 IN3 |
| ESP IO15 | ULN2003 IN4 |

- **接上任何板子之前，先用電表把 LM2596 輸出調到 5.0V。** 出廠電壓可能遠高於 5V，直接接會燒板。
- 馬達五線接頭插 ULN2003 的馬達座，不要把馬達線直接接 ESP。
- 馬達電流從 LM2596 直接拉到 ULN2003，不要經過 ESP 板子。
- 建議在 ESP 的 5V 與 GND 之間並一顆 470–1000µF 電解電容（注意極性），減少馬達干擾造成重開機。
- ESP32-CAM 排針上有一個標 GND 的腳在這塊板子實測不是 GND（曾造成燒錄失敗）。接之前先用電表確認 GND 腳。
- 不插 microSD、不接相機。IO4 接著閃光燈 LED，不使用。

## 電源估算

ESP 開 Wi-Fi 時峰值約 0.3A，馬達約 0.2A，合計約 0.5A，LM2596 足夠。變壓器 1A 就夠。輸入要比 5V 高約 2V 才穩，所以用 9–12V。這些是估算值，尚未實測。

## 腳位風險（待實機確認）

- **IO12** 開機時必須是低電位，否則 ESP 開不了機。ULN2003 輸入會往低拉，應該沒問題；如果接上驅動板後開不了機，先查這支。
- **IO14、IO15** 開機瞬間可能有訊號，馬達也許抖一下，造成 1–2 步誤差。若每次重開機誤差會累積，要另外處理。

## 序列救援（OTA 失敗才需要）

馬達先斷電。用 3.3V 邏輯的 USB 轉 TTL 轉接板，或把 Uno 當轉接：

| 轉接 | ESP32-CAM |
|---|---|
| TX | U0R（IO3） |
| RX | U0T（IO1） |
| GND | GND |

再把 ESP 的 **IO0 接 GND**，按 RST 進入下載模式，執行 VS Code Task「ESP：序列燒錄（救援用）」。完成後拔掉 IO0→GND，再按一次 RST。

用 Uno 當轉接時：Uno RESET 接 GND（讓 Uno 自己不跑），D0/RX 與 D1/TX 是 5V 邏輯，要經電平轉換（HW-209 的 B0→A0 接 U0R、A1→B1 接 D1）。Uno 上的程式不影響轉接。

依據：[TI ULN2003A](https://www.ti.com/lit/ds/symlink/uln2003a.pdf)。
