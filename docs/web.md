# 網頁操作台（ESP 韌體 0.3.0）

ESP32-CAM 開機後建立 Wi-Fi 熱點 `FlipClock-xxxx`（xxxx 為裝置序號後四碼）。手機連上後開 `http://192.168.4.1/`，帳號 `admin`，密碼為裝置首次開機隨機產生並存入 NVS，用 UART 指令 `access` 讀取。熱點使用 WPA2；網頁沒有公網服務，只適合現場使用。

## 流程

1. **校時**：用手機時間與時區寫入 DS3231。
2. **手動歸零**：只能正向轉動（+1／+8／+32／+136 步）。轉到看得出時間的位置後，輸入實際顯示的時間與每頁步數，按「記住為歸零位置」。這一步同時確認機構、週期 720 分鐘、速度上限 200 步／秒與加速度 800。
3. **試跑確認**：連續前進 1:07、3:01、4:01 三組差異較大的時間，每組換頁後核對實際顯示。不符時輸入實際顯示：頁數誤差在合理範圍會建議新的每頁步數，並以實際顯示重新對齊，從試跑 1 重來。
4. **完成歸零**：儲存位置與設定，預覽並以「允許大量補跑」恢復走時。

「暫停走時」和「緊急停止」隨時可用。緊急停止會使位置失效，需重新確認顯示。

## 斷電重啟

- 走到目標時間（換頁完成）就儲存位置快照，包含頁碼與步數餘數。
- 開機時，若快照存在且機構已確認，就載入位置；RTC 有效且 Uno 連線後自動補跑到目前時間，補跑不受「大量補跑確認」限制。
- 操作者的任何指令（暫停、停止、歸零、移動等）都會取消尚未執行的自動恢復。

**已知限制（沒有原點感測器）：**斷電發生在換頁途中，或補跑途中，快照會落後實際位置，補跑後顯示會偏差，需在網頁重新輸入實際顯示。開機後請確認一次顯示，不要只憑記憶。

## 範圍

- `/api/cmd` 使用與 BLE 相同的指令（`v`／`id`／`boot_id` 由韌體補上），沒有新增控制路徑。
- 網頁指令不經 BLE 的請求去重表，因此 BLE 的 id 單調性不受影響。
- HTTP 為明文 Basic 認證；請勿把熱點橋接到公網。
