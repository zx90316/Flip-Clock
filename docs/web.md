# 網頁操作台（ESP 韌體 0.4.7）

ESP32-CAM 開機後建立 Wi-Fi 熱點 `FlipClock-xxxx`（xxxx 為裝置序號後四碼）。手機連上後開 `http://192.168.4.1/`；網頁與熱點共用首次開機隨機產生、存入 NVS 的密碼，可用 UART 指令 `access` 讀取。熱點使用 WPA2；網頁沒有公網服務，只適合現場使用。

控制台在桌面版使用側邊導覽、裝置總覽與設定卡片；手機版的導覽可橫向滑動。畫面依序呈現步數規劃、校時與歸零、直接儲存、選用的手動進步與前進檢查、Wi-Fi、安全設定和 OTA 更新。操作訊息短暫顯示在畫面底部。

## 流程

1. **校時**：連上家中 Wi-Fi 取得 NTP 時間，或暫時使用手機時間；裝置沒有電池 RTC。
2. **檢查步數**：頁面顯示生效及已儲存的每分鐘半步數、累積餘數、後續 10 次換頁與 30 次合計。編輯草稿會另行試算，不會立即改動裝置。
3. **歸零**：輸入時鐘實際顯示，按「以此歸零」；翻片卡在臨界角度時可選用「手動進步」。
4. **儲存並走時**：可直接儲存設定及位置並恢復自動走時。前進幾分鐘核對實際顯示是選做，不影響儲存按鈕。

「暫停走時」和「緊急停止」隨時可用。緊急停止會使位置失效，需重新確認顯示。

## 斷電重啟

- 走到目標時間（換頁完成）就儲存位置快照，包含頁碼與步數餘數。
- 開機時，若快照存在且機構已確認，就載入位置；取得網路時間後自動補跑到目前時間，補跑不受「大量補跑確認」限制。
- 操作者的任何指令（暫停、停止、歸零、移動等）都會取消尚未執行的自動恢復。

**已知限制（沒有原點感測器）：**斷電發生在換頁途中，或補跑途中，快照會落後實際位置，補跑後顯示會偏差，需在網頁重新輸入實際顯示。開機後請確認一次顯示，不要只憑記憶。

## 範圍

- `/api/cmd` 使用與 BLE 相同的指令（`v`／`id`／`boot_id` 由韌體補上），沒有新增控制路徑。
- 網頁指令不經 BLE 的請求去重表，因此 BLE 的 id 單調性不受影響。
- HTTP 為明文傳輸，登入後的請求使用 Bearer token；請勿把熱點橋接到公網。

## OTA 韌體更新

首次必須用 UART 燒錄含雙 OTA 分區（min_spiffs）的韌體，之後在網頁最下方選 dist/esp32_clock/esp32_clock.ino.bin（不是 merged、bootloader 或 partitions 檔）上傳即可。

- 只在馬達閒置且已斷開時接受；上傳開始時自動暫停走時。
- 映像開頭與長度先檢查，Update 程式庫在結束時驗證映像；失敗或中斷不會切換分區，原韌體照常運作。
- 成功後 ESP 約 20 秒內重新啟動，NVS 內的位置、設定與網頁密碼保留，並依位置自動恢復。
- 若 ESP 因韌體問題連網頁都開不了，仍需回到 UART 燒錄救援。

## 速度與加減速

- 速度上限 1000 步／秒、加速度上限 4000 步／秒²。頁面載入裝置目前的設定值，新裝置初始為 200／100，可在歸零步驟修改；**高速度尚未在實機驗證，馬達只嗡嗡響、抖動或漏步時請調低。**
- 每次移動都從慢速起步、加速，接近終點前依剩餘距離減速：`速度 = min(上限, √(2×加速度×min(已走距離, 剩餘距離)))`。
- 多頁（歸零試跑、開機補跑）合併成**一次連續移動**，每次最多 9000 步（約 65 頁），中間才有機會衝到高速；單頁移動的三角形速度曲線最高只有 √(加速度×頁步數)，所以調高上限對單頁幫助有限。
- 轉動按鈕最大 +2720 步（20 頁），`jog_steps` 最大 8000 步，`advance_pages` 最大 720 頁。
- 移動逾時 = 估計時間 × 1.5 + 5 秒，避免計時抖動在高速時誤判逾時。
- **行為改變：**「暫停走時」會等目前這一段連續移動走完才停（最多約十幾秒）；要立即停用「緊急停止」，但位置會失效。

## Wi-Fi 設定（選填）

網頁「Wi-Fi 連線」：掃描附近網路（去重、依訊號排序、最多 20 筆）→ 點選 → 輸入密碼 → 「測試連線並儲存」。

- Wi-Fi 名稱和密碼存在 NVS，斷電不會消失。開機或既有連線中斷後，裝置最多在 60 秒內嘗試舊網路兩次；有人連入裝置熱點時會停止背景重試。超時後熱點保持開啟，不會再自動試舊網路，直到在網頁按「重試已儲存 Wi-Fi」或重新開機。
- **連上才儲存新網路。** 密碼錯誤、找不到、試連超過 45 秒或連上後儲存失敗，都不會改動舊設定。只有試連前確實連著舊網路，失敗後才嘗試恢復舊連線；在新地點舊網路收不到時，直接回到穩定熱點。
- 密碼只在 HTTP 請求中送一次，不回傳、不寫入日誌，試連結束後清除 RAM 緩衝。
- 掃描、手動重試與測試新網路時，熱點可能跟著 STA 換頻道而短暫中斷，頁面會自動重連並顯示結果。背景重試停止後，不會週期性打斷熱點。
- 網頁顯示的網路名稱以純文字渲染，不會被鄰居的惡意名稱注入。
- 勾選「用網路自動校時」後每 6 小時對時。誤差 5 分鐘內時，走時中的時鐘**不會停**；超過 5 分鐘會暫停並在頁面上要求確認。
- 藍牙設定 Wi-Fi 尚未實作；UART 的 `wifi {"ssid":..,"password":..}` 仍可用。

## 修正

背景存檔進行時按「暫停」，存檔結束後會被還原成走時中，暫停被吞掉。現在存檔期間發生的暫停、停止、設定或位置變更都會保持暫停（有測試）。

## 時間來源：只用網路時間（無 RTC）

- 沒有 RTC 模組，也沒有電池保持時間。
- 時間完全來自 Wi-Fi 的 NTP（每 6 小時校正）。開機後在第一次取得網路時間前，狀態顯示「等待網路時間」，時鐘不會移動；取得後才依儲存的位置自動補跑。
- **因此必須先在網頁設定好 Wi-Fi。** 沒有網路時，可按「暫時用手機時間」撐著，但斷電後會消失，且連上網路後仍會被網路時間修正（差超過 5 分鐘要確認）。
- 時區仍是設定值（`utc_offset_min`，預設 UTC+8），可按「時區設為手機時區」。
- 兩次校時之間由 ESP32 石英震盪器計時，誤差約每天 1～2 秒，每 6 小時修正一次。

## 登入與密碼

- 網頁改為登入頁，不再跳出瀏覽器的帳號密碼視窗。登入後憑證存在瀏覽器的 `localStorage`，沒有期限，換瀏覽器或換網址（例如熱點 ↔ 區網）要各登入一次。
- 密碼同時是網頁密碼和熱點 Wi-Fi 密碼。「更改密碼」需要目前密碼；新密碼 8–63 個英數字或符號。更改後憑證也會換新，其他瀏覽器要重新登入，用熱點連線的裝置要用新密碼重連。
- 連續輸錯 5 次鎖定 30 秒。忘記密碼時可從 UART 輸入 `access` 查看。
- 連線是一般 HTTP，密碼與憑證在區網上沒有加密。

## 歸零流程（新版）

1. **歸零**：輸入時鐘現在顯示的時間，馬達不轉。
2. **手動進步（選做）**：輸入 1–8000 個整數半步，或按 +1／+4／+8／+32，馬達只向前走這一次。裝置記住的顯示位置、餘步、設定及儲存次數均不變。若實際翻片因此換頁，請重新歸零。
3. **驗證（選做）**：指定任意分鐘數（1–720）前進，再對照實際顯示，可重複；可略過此步直接儲存。
4. **儲存**：若曾前進驗證，顯示可能比現在快；時鐘只能往前轉，快 60 分鐘以內時會先停著等時間追上，狀態顯示「等時間追上」，也可按「現在轉一圈對時」。
   手動進步不寫入 NVS；原有設定與憑證格式保持相容。

每分鐘步數預設 136.533333 個半步，裝置只會送出整數半步，餘數以百萬分之一步記帳並在後續換頁時進位。從餘數 0 起算，30 次換頁共走 4095 步，餘數 999990／1000000 步。頁面分開列出目前設定與草稿的規劃；實際位置未知時不顯示可用的餘數，移動中待完成後才更新規劃。已儲存舊預設 136 的裝置，開機後生效值會轉為新預設但標記為未儲存；重新歸零後可直接儲存，前進驗證為選做。
